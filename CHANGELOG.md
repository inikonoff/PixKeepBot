# Changelog

Все версии PixKeep Bot (в коде и сессиях разработки он раньше назывался
CleanDrive). Новые сверху. Даты проставлены только там, где они известны;
для ранних версий история датами не велась.

Подробные технические комментарии к каждой версии остаются в шапке `main.py`
(и в шапках `db.py`, `drive_utils.py`, `photo_fix.py`). Текущую версию
запущенного бота показывает команда `/version`.

---

## v5.23 — 2026-10-28
Пакет улучшений вокруг нескольких аккаунтов и больших пачек.
- **Свободное место по аккаунтам.** `/accounts` показывает «занято X из Y»
  у каждого аккаунта; перед загрузкой бот предупреждает, если пачка не
  помещается; в отчёте — строка «💾 занято…». Квота берётся через Drive
  `about.get`; если Google её не отдаёт, вместо цифр показывается «?» и
  ничего больше не ломается.
- **Пропуск дубликатов.** Файлы сравниваются по md5 — внутри пачки и с тем,
  что уже лежит в целевой папке; повторы не загружаются, в отчёте строка
  «♻️ Уже есть в папке, пропущено…». Исходные сообщения таких файлов
  удаляются как и у загруженных. В txt-списке помечены `duplicate, skipped`.
- **Подсказки папок.** Под вопросом об имени папки — кнопки: сегодняшняя
  дата и последние папки, созданные ботом на активном аккаунте.
- **Прогресс и повтор.** Во время загрузки одно сообщение обновляется
  («Загружаю… 3/12»), после отчёта оно исчезает. Под отчётом при ошибках —
  «🔁 Повторить неудачные»: файлы хранятся 30 минут.
- **«Мои загрузки»:** «✏️ Переименовать папку» и «📥 Прислать файл в чат»
  (скачивание с Диска, до 50 МБ — лимит Bot API на отправку).
- При старте бот очищает временную папку от остатков прошлого запуска.
- `drive_utils` v4.4 (get_quota, list_folder_md5, list_recent_folders,
  rename_file, get_file_meta, download_file), `db` v5.8 (rename_folder_rows).

## v5.22 — 2026-10-28
- `/accounts`: под списком аккаунтов кнопка «➕ Добавить аккаунт».

## v5.21 — 2026-10-27
- Бот принимает **любые** файлы: добавлены видео, аудио, голосовые, кружки и
  GIF (раньше — только фото и документы, остальное молча игнорировалось).
- Исправлено: один не скачавшийся файл (например, больше 20 МБ — лимит Bot
  API на скачивание) ронял всю пачку без сообщения. Теперь такие файлы
  перечисляются в отчёте, остальные грузятся, их сообщения остаются в чате.
- Исправлено: файлы с одинаковым именем в одной пачке перезаписывали друг
  друга на диске (и оба исходных сообщения удалялись). Теперь получают
  суффикс `_2`, `_3`…
- Если exiftool не смог почистить файл, бот молча загружал его как есть.
  Теперь предупреждает в сообщении и помечает в txt-списке
  `[metadata NOT cleaned]`.

## v5.20 — 2026-10-27
- **Комментарии к папке.** Кнопка «💬 Добавить комментарий» под отчётом о
  загрузке и в карточке загрузки. Текст сохраняется в `!COMMENT.txt` (имя с
  «!», чтобы файл шёл первым): один файл на папку, комментарии дописываются
  с меткой времени, кириллица — в UTF-8 с BOM. Комментарий можно удалить из
  «Мои загрузки».
- Новые колонки `uploads.comment`, `uploads.comment_file_id` (SQL в README).
- Старые записи истории с комментарием не вычищаются при ротации.

## v5.19 — 2026-10-27
- Автокоррекция переписана: «тёмное ли фото» и сила подъёма считаются по
  теням (20-й процентиль яркости), а не по медиане; вместо общей гаммы —
  кривая подъёма теней (света не трогаются). Раньше кадр с тёмным передним
  планом под светлым небом в режиме «авто» пропускался, а в «всегда» подъём
  был почти незаметен.

## v5.18 — 2026-10-26
- При включённой чистке метаданных фото с тегом EXIF Orientation
  физически поворачиваются до чистки (`exiftool -all=` удаляет тег, и
  вертикальные кадры иначе ложились бы на бок). JPEG пересохраняется с
  quality 95; в txt-списке такие файлы помечены `rotated upright`.

## v5.17 — 2026-10-26

- **Список файлов (txt)**: в папку кладётся `upload_list_<дата>.txt`

- Зависимость: Pillow.
